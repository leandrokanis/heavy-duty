# Política de segurança

## Relato de vulnerabilidade

Não abra issue pública para vulnerabilidade. Use o relato privado de vulnerabilidade do GitHub, na aba Security do repositório [a confirmar: ativar o recurso quando o repositório for publicado].

Inclua no relato:

1. O componente afetado (`apps/ui`, `apps/api` ou servidor MCP).
2. Os passos para reproduzir.
3. O impacto esperado.

## Versões com correção

Só a versão da branch `main` recebe correção de segurança.
